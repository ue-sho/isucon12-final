# ADR-0003：AIによる根拠付き分析

状態：提案。2026-10-12。

## 背景

AIにendpoint、SQL、OS指標、Profileを横断して調査させたい。ただしサンプル偏り、単位、集計窓、並列Span、欠損を誤解すると誤った最適化につながる。

## 課題

自由SQLだけでは誤ったJOINや全件走査を防げない。read-onlyでも外部接続・ファイル参照等の機能を含む処理系がある。集計JSONだけでは根拠を掘り下げられない。MCPは通信方式であり、正確さや安全性の保証ではない。

## 選択肢

| 方式 | 強み | 弱み |
|---|---|---|
| DBへ自由SQL | 探索能力が高い | SQL方言・データモデルの誤解、資源消費、権限管理 |
| MCPで定型問い合わせ | 実行ID、単位、件数制限を統一できる | API実装・保守が必要、探索範囲が狭くなる |
| 事前集計JSON | 単純、再現可能、低コスト | 集計から落ちた情報に気付けない |
| 集計JSON + 根拠参照CLI | 導入が軽く、必要な原本まで辿れる | 検索・問い合わせの契約を定義する必要 |

## 結論

MVPは集計JSON + 根拠参照CLIを採用する。実行、route、query fingerprint、trace、profileの参照を定型化し、CLIと将来のMCPで同じ結果契約を使う。任意SQLは検証後の上級機能にする。

AIの出力はObservation/Evidence/Hypothesis/Confidence/Validation/Proposed Change/Expected Impact/Benchmark Comparisonを必須にする。観測対象数、sampling、欠損、期間、計測モード、問い合わせ条件を根拠に含める。

## 影響

AIが任意に本番DBへEXPLAIN ANALYZEしたり、改善を自動適用したりしない。問い合わせ失敗は空データと区別する。取得したログ・SQL・メモはデータとして扱い、含まれる命令を実行しない。

## 再検討条件

定型問い合わせでは調査が進まない事例を記録できた場合。許可ビュー、単一SELECT、外部関数禁止、時間・メモリ・走査量・返却量制限を適用したSQLアクセス、またはMCPを追加する。
